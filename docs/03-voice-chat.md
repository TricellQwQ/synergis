# 03 — Пространственный голосовой чат

## 0. Главная новость: он уже есть

Я залез в исходники EW и нашёл в прокси готовую реализацию **позиционного голосового чата**:
`mods/noita_entangled_worlds-master/noita-proxy/src/net/audio.rs` (300 строк).

Это не заготовка — это рабочая система:

- **Захват микрофона:** `cpal` (default input device или выбранное устройство).
- **Ресемплинг:** `rubato` (`FftFixedIn`) в 48 кГц.
- **Кодек:** Opus, моно, `FRAME_SIZE = 960` сэмплов = **20 мс** на кадр, `Application::Audio`.
- **Воспроизведение:** `rodio`, отдельный `Sink` **на каждого говорящего** (`per_player: HashMap<OmniPeerId, PlayerInfo>`), декодирование Opus на приёме.
- **Пространственность:** громкость = `volume[peer] / (1 + dropoff * dist * 2^-18)` при
  `dist <= range`, иначе `0`. То есть **затухание по расстоянию с жёстким обрезом на радиусе**.
- **Позиция источника:** отправитель шлёт свою позицию вместе с аудио (`NetMsg::AudioData(data, global, x, y, vol)`),
  и это может быть позиция игрока **или камеры** (настройка `player_position`).
- **«Глобальный» голос:** флаг `global` = «have voice always be played» — превращает
  пространственный звук в радио/глобальный канал.
- **Push-to-talk** (по умолчанию **T** в Noita), loopback, mute in/out, авто-мьют
  **пока мёртв** и **пока полиморфнут** (для БР это ровно то, что нужно), персональная
  громкость каждого игрока, выбор устройств ввода/вывода, `global_input_volume`/`global_output_volume`.

Заодно в коде видны **незавершённые вещи** — они прямо помечены комментариями:

- **Окклюзия стенами не сделана** (`walls_strength`, `max_wall_durability` закомментированы).
- **Доплер/питч-шифт не сделан** (целый `VelocityTracker` и DSP-ресемплер `resynth` закомментированы;
  в коде даже заготовлена константа скорости звука и `PIXELS_PER_METER = 14.0/1.7`).

## 1. Что это значит для твоего плана

**Требование №3 из твоего ТЗ уже выполнено чужими руками, и довольно качественно.**
Тебе не нужен ни sidecar, ни Mumble, ни своя DLL. Нужно:

1. Включить и настроить голос в GUI прокси (ползунки `dropoff`, `range`, устройства, PTT).
2. Проверить, что он работает в вашем коопе.
3. Опционально — доработать под БР (см. ниже).

Это экономит тебе, по грубой оценке, 1–3 недели работы и целый класс проблем
(синхронизация аудио с отдельным приложением, выбор устройств, NAT).

## 2. Чего в голосе EW НЕТ и что имеет смысл допилить под БР

Это и есть твоя возможная зона вклада. По убыванию полезности для баттл-рояля:

| Что | Зачем в БР | Сложность |
| --- | --- | --- |
| **Командные каналы** | Сейчас голос — один общий канал с затуханием. Нет понятия «слышат только свои». В дуо/скваде это обязательно. | Средняя: правка Rust (прокси) + передача team id из мода |
| **Привязка слышимости к зоне/статусу** | Мёртвые уже мьютятся (`mute_in_while_dead`). Хочется ещё «вне зоны — голос глушится искажением». | Средняя |
| **Окклюзия стенами** | Пространственность станет честной: за стеной слышно глухо. Автор уже начал и бросил — есть куда встроиться (`walls_strength`). | Высокая: нужен доступ к карте мира из прокси (у EW уже есть `world_sync` и `GetFogOfWar`-подобные данные) |
| **Доплер** | Приятная мелочь, код уже написан и закомментирован. | Низкая (раскомментировать/починить) |
| **Передача «говорит сейчас» в игру** | Индикатор над головой говорящего игрока в стиле L4D/Fortnite. | Низкая-средняя: прокси → Lua → UI |
| **Хост-контроль голоса** | Сейчас `global` — это клиентская настройка отправителя (то есть «включаю себе радио» решает сам игрок). Для честного БР хотелось бы решать хосту. | Средняя |

## 3. Если всё же захочется свой голосовой слой (на случай форка)

Оставляю здесь как справку, чтобы ты понимал ландшафт, если решишь форкать прокси
или писать отдельное приложение.

**Почему нельзя сделать голос внутри игрового мода:** в Lua-API Noita нет ни захвата,
ни воспроизведения аудиопотока, ни сокетов. Аудио-функции ограничены проигрыванием
событий FMOD:

```
GamePlaySound(bank_filename, event_path, x, y)
GameEntityPlaySound(entity_id, event_name)
GameEntityPlaySoundLoop(entity, component_tag, intensity, intensity2)
ModRegisterAudioEventMappings(...), ModRegisterMusicBank(...)
```

`GamePlaySound` принимает координаты, то есть **умеет позиционировать звук** — но это
событие из заранее собранного `.bank`, а не поток. Подсунуть туда живой голос невозможно.

Значит любой «свой» голос = внешний процесс. Три варианта, по возрастанию качества:

1. **Файл как шина.** Мод (с `request_no_api_restrictions="1"`) пишет позиции игроков
   через `io.*` в файл 10–20 раз в секунду, внешнее приложение читает. Прототип — вечер.
   Минус: опрос диска, нет событий, latency.
2. **Свой нативный Lua-модуль.** Ровно как `ewext.dll`: собираешь `.dll` (Lua C-модуль)
   и грузишь через `package.cpath` + `require`. Получаешь настоящие сокеты/UDP прямо из Lua.
   Минус: тулчейн (`i686-pc-windows-gnu`, см. `Justfile` в EW) и Rust/C.
3. **Свой форк прокси.** У прокси уже есть Steam-lobby, NAT-punch и весь Opus-пайплайн —
   встроить голос в тот же канал дешевле, чем поднимать отдельную сессию.

## 4. Что нужно от твоего мода для голоса

Даже если голос делает прокси, мод должен отдавать корректные данные. Прокси берёт позицию
отправителя из `NetMsg::AudioData` — то есть из позиции игрока/камеры, которую EW и так
синхронизирует. **От тебя ничего не требуется**, кроме одного: следить, чтобы при телепортах
высадки и в зоне позиция была осмысленной (иначе голос будет «прыгать» по карте).

Приятный побочный эффект: если игрок мёртв и стал спектатором, EW-настройки
`mute_in_while_dead` + `spectate` дают корректное поведение «мёртвые не мешают».

## 5. Вывод

**Не трогай голос на старте.** Сначала включи существующий, поиграй неделю, и только потом
решай, чего не хватает. Наиболее вероятный вывод: не хватает **командных каналов** — это и
будет твоя доработка. Всё остальное — полировка.
