# 04 — Баттл-рояль: дизайн и план работ

> **РЕШЕНИЕ ПРИНЯТО: идём по дизайну B — классический сужающийся круг.**
> Разбор кода под этот выбор: [`docs/06-pvp-lua-walkthrough.md`](06-pvp-lua-walkthrough.md).
> Это меняет приоритеты: M8 (кастомная генерация) поднимается в приоритете — на ванильном
> мире гигантского размера круг работает плохо, а компактная арена становится условием,
> а не улучшением. Плюс появляются две новые задачи до M6: «все игроки в одном параллельном
> мире» и «политика Holy Mountain». Подробности — в конце `docs/06`.

## 1. Честная оценка до начала

Твоя задумка — это **три проекта**, а не один:

1. Логика БР поверх EW (реалистично, ~1.5–3 месяца вечерами до играбельного вертикального среза).
2. Кастомная процедурная генерация под арену (отдельный большой кусок, от 1 месяца).
3. Голосовой чат — **уже сделан в EW** (см. `docs/03`), доработки по желанию.

Плюс постоянный налог: EW — сторонний мод, он ломается при обновлениях игры, и все игроки
должны иметь одинаковый набор модов и версий.

Это не «не делай». Это «делай по этапам и не начинай с генерации».

## 2. Два возможных дизайна. Выбирай осознанно

### Дизайн A — «раундовый» (рекомендую для v1)

Ровно то, что уже работает в EW PvP (`files/system/pvp/pvp.lua`):

- игроки разбрасываются по случайным чанкам **одного биома**;
- таймер (например 90 сек) — это и есть «зона»: после него все выжившие
  насильно телепортируются в следующий биом, начиная новый раунд;
- умер = выбыл (perma-death), выживший получает очко/сундук;
- глубина растёт → биомы становятся злее → естественная эскалация;
- побеждает последний выживший / последняя команда.

**Почему для Noita это лучше классики:** мир огромный и вертикальный, игроки умеют копать
и летать, левел-дизайн не рассчитан на арену. Круг, ползущий по такому миру, превращается
в «все копают вниз». А раундовая схема сама создаёт и границу, и темп, и точку встречи.

Технически: 70% механики уже написано в `pvp.lua`, ты его переписываешь под свои правила.
Это реально быстро и даёт играбельный результат.

### Дизайн B — «классический сужающийся круг»

- настоящий круг с центром и радиусом, фазы сужения, урон вне зоны;
- красиво и понятно, но в ванильном мире работает плохо (см. выше).

**Где он становится хорош:** если совместить с M8 — сгенерировать **компактный мир-арену**
(своя `biome_map.lua` + уменьшенный `BiomeMapSetSize`, 2–4 биома, никакой копки в бесконечность).
Вот тут кастомная процедурная генерация действительно нужна и окупается: она даёт
правильную площадку для настоящего БР.

**Мой совет:** v1 = Дизайн A на ванильном мире. v2 = Дизайн B на кастомной арене (M8).
Ты получишь играбельный режим через недели, а не через месяцы, и не будешь полировать
круг на мире, который для него не предназначен.

## 3. Архитектура

### Где какой код живёт

| Слой | Где | Что там |
| --- | --- | --- |
| Сетевой модуль EW | `files/net/module.lua` (в контексте EW) | состояние матча, зона, таймеры, RPC, host-authoritative логика. Видит `ctx`, `net`, `rpc` |
| Мост в игровой контекст | `ModLuaFileAppend` + `np.CrossCallAdd` | вызвать игровой код (спавн, хуки генерации) из сетевого модуля и наоборот |
| Генерация | `files/magic_numbers/*.lua` + `ModMagicNumbersFileAdd` | своя `BIOME_MAP` (M8) |
| Настройки | `settings.lua` | конфиг матча, `ModSettingGet("synergis.*")` |
| Настройки от хоста | RPC + `rpc.create_var` | «серверные» правила, разосланные всем |
| HUD | `GuiCreate`/`GuiText` в `on_world_update` | таймер, счёт живых, зона. Образец — `pvp.lua` |
| Урон/здоровье | `ctx.cap.health` | capability-слой EW (см. ниже) |

### Ключевой API для урона и здоровья

EW описывает capability-слой в `mods/noita_entangled_worlds-master/docs/capabilities.md`:

```lua
ctx.cap.health.health() -> num
ctx.cap.health.max_health() -> num
ctx.cap.health.set_health(hp)
ctx.cap.health.set_max_health(hp)
ctx.cap.health.inflict_damage(dmg)      -- ← урон вне зоны делать ЭТИМ
ctx.cap.health.do_game_over(msg)
ctx.cap.health.on_poly_death(msg)
```

Смысл capability в том, что активна ровно одна реализация (общий HP или локальный HP на
игрока), и твой код не должен знать, какая. **Не лезь в `DamageModelComponent` напрямую** —
используй `ctx.cap.health`, иначе сломаешься при смене режима в прокси.

### Модель времени: `ctx.host_frame_num`

Чтобы не гонять радиус зоны по сети каждый кадр: хост рассылает **фазовую запись**
(reliable, один раз), а клиенты интерполируют локально от `GameGetFrameNum()`, сверяясь
с `ctx.host_frame_num`. Это стандартный приём и он уже есть в EW.

## 4. Машина состояний матча

```
LOBBY
  └─ ждём N игроков / все нажали ready → хост стартует
DROP
  ├─ выбрать точки высадки (чанки биомов, см. chunks_by_floor)
  ├─ телепортировать каждого (образец: pvp.teleport_into_biome)
  ├─ выдать стартовый жезл (образец: starting_loadouts)
  └─ prep-фаза: инвентарь закрыт, неуязвимость, обездвиженность (см. safe_effect.xml)
PLAY
  ├─ фаза 1..N: таймер, сужение/переход, урон вне зоны, лут
  ├─ отслеживание смертей (perma-death + спектатор)
  └─ проверка условия конца (живых <= 1 для solo, <= 1 команды для team)
RESULTS
  ├─ таблица (образец create_board в pvp.lua)
  └─ рестарт матча без перезапуска игры
```

Всё состояние матча живёт **только на хосте**. Клиенты получают: фазу, таймеры, состав
команд, точки высадки, конец матча. Всё остальное (позиции, смерть, инвентарь, лут)
уже синхронизирует EW — не дублируй.

## 5. Зона: как сделать её реально

| Аспект | Решение |
| --- | --- |
| Модель | центр (x, y) + радиус + номер фазы, в мировых пикселях. 1 чанк = 512 px |
| Передача | reliable-RPC на смену фазы; внутри фазы клиенты интерполируют сами |
| Визуал | `ParticleEmitterComponent` на сущности-маркере. **Готовый образец:** `quant.ew/files/system/player_tether/zone_entity.xml` + `set_tether_length()` — там уже параметризован радиус частиц |
| Урон | только хост решает, кто вне зоны; применяет через `ctx.cap.health.inflict_damage(...)` |
| Мягкий вариант | телепорт обратно внутрь (механика `player_tether`, настройка `zone_teleport_back`) |
| HUD | круг/иконка на карте (образец: `quant.ew/files/system/map/`) и текст таймера (`GuiText`) |
| Эскалация | каждая фаза: радиус × 0.7, скорость × 1.2, урон × 1.5 |

## 6. Высадка (DROP)

Готовый рецепт лежит в `pvp.lua` → `pvp.teleport_into_biome()` (строки 503–549), включая
неочевидные детали: выключить `InventoryGuiComponent`, поставить `mDesiredCameraPos`,
после телепорта проверить `RaytracePlatforms` вниз и повторить, если угодил в стену,
и «подбросить» игрока (`float()`).

Что нужно от тебя поверх:

- выбрать **разные** чанки (чтобы игроки не появились в одном месте);
- обездвижить и обезопасить на prep-таймер (`safe_effect.xml`);
- выдать стартовый жезл;
- иметь фолбэк, если чанк не загружен (`DoesWorldExistAt`).

## 7. Лут

Два слоя, использовать оба:

1. **Детерминированный лут по координатам** (основной).
   `ProceduralRandomi(x, y, ...)` в точке, привязанной к чанку. Каждый клиент сам решает,
   что лежит в этой точке, и получает то же самое. Ноль трафика.
   Для «одинаковости» сущностей EW поддерживает тег **`ew_unique`**: *«kills an entity if
   another one was spawned within the same chunk on any peer, by filename»* — то есть
   дубликаты от разных клиентов сами схлопываются. Это идиоматичный для EW способ.
2. **Host-authoritative спавн** — когда нужен «настоящий» рандом (сундук с рероллом).
   Образец: `quant.ew/files/system/gen_sync/gen_sync.lua` — хост выполняет
   `generate_shop_item`/`generate_shop_wand`, и результат глобализуется
   через `ctx.cap.item_sync.globalize(eid, true, peer_id)`.

Тир лута: `BiomeMapGetName(x, y)` (какой биом) и `BiomeMapGetVerticalPositionInsideBiome(x, y)`
(насколько глубоко внутри биома). Ограничивай сверху настройкой `loot_tier_cap`, иначе
в глубоких биомах БР превратится в «у кого случайно выпал имба-жезл».

## 8. Смерть, команды, победа

- **Perma-death**: режим `LocalPermadeath` в прокси + `local_health` в EW. Умер — выбыл.
- **Спектатор**: EW имеет готовую систему `spectate` — не пиши свою.
- **Команды**: помечай игроков herd-id. В Noita есть `StringToHerdId(name)`,
  `EntityGetHerdRelation(a, b)`, `GenomeSetHerdId(...)` — это нативный способ «свой/чужой».
  Для урона между игроками проверяй команду перед нанесением.
- **Условие победы**: хост считает живых и живыe команды, при `<= 1` рассылает `rpc.match_over`.
- **Учёт убийств**: в EW уже есть `StatsLogPlayerKill` и система `damage` — посмотри
  `files/system/pvp/pvp.lua` (`pvp.last_damage`) как определяется убийца.

## 9. План по этапам

Оценки — «вечерами после работы», для одного человека, знакомого с Lua но не с Noita.

| Этап | Что делаешь | Оценка |
| --- | --- | --- |
| **M0** | Тулчейн и каркас режима: распаковать `data.wak`, поставить luacheck, `mod.xml` как игровой режим, `init.lua` с хуками, наладить отладочный лог (вывод Lua **не** попадает в `logger.txt` — см. `docs/00` §6) | 1–2 вечера |
| **M1** | Игровой режим: `mod.xml` как game mode, баннер, хуки, режим виден в меню New Game | 1 вечер |
| **M2** | Сеть: EW запускается в кооперативе вдвоём, свой модуль, RPC-hello, ники и `peer_id` с обеих сторон | 2–3 вечера |
| **M3** | Каркас матча: состояния Lobby→Drop→Play→Results, таймер, HUD, без зоны и лута | 3–5 вечеров |
| **M4** | Высадка: разные чанки, prep-фаза, стартовый жезл, безопасное приземление | 3–5 вечеров |
| **M5** | Лут: детерминированный по координатам + синхронизация + тиры | 3–5 вечеров |
| **M6** | Зона: визуал частицами, урон через `ctx.cap.health`, телепорт-ограничение | 4–6 вечеров |
| **M7** | Победа, счёт, спектаторы, рестарт матча без перезапуска игры | 3–5 вечеров |
| **M8** | Кастомная генерация под арену (своя `biome_map.lua`, компактный мир) | 3–6 недель |
| **M9** | Доработки голоса (командные каналы и т.п.) | 1–2 недели |
| **M10** | Полировка, настройки, README, упаковка, инструкция для друзей | 1–2 недели |

**M0–M7 = играбельный вертикальный срез БР.** Это и есть цель v1. Всё после — улучшения.

## 10. Риски и что с ними делать

| Риск | Что делать |
| --- | --- |
| EW ломается после патча Noita | Пинить версию. Не обновлять игру, пока не играете. Держать `logger.txt`/`ew_log.txt` под рукой. |
| Рассинхрон | Всё «общее» — только на хосте. Детерминированный лут вместо рассылки. `flag_sync` для флагов. |
| Клиенты читерят | Принять как данность (игра с друзьями). Не строить публичное лобби. |
| Набор модов разошёлся | Чёткий список в README мода, версия EW указана явно. |
| Сильно разрастается | Резать фичи. Дизайн A вместо B. Ванильный мир вместо своего. |
| Выгорание на «своей генерации» | M8 в самом конце и по желанию. БР играбелен без него. |

3. Пройди M0 и M1. Это скучно и не про геймплей, но без этого всё остальное — гадание.
4. Возвращайся, и мы сделаем M2/M3 вместе.
