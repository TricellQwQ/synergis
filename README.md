# Synergis

Баттл-рояль для Noita: игроки высаживаются в разных локациях, собирают жезлы и спеллы,
зона сужается, побеждает последний выживший или последняя команда.
Мультиплеер обеспечивает [Quant's Entangled Worlds](https://github.com/IntQuant/noita_entangled_worlds).

Этот файл - документация для меня для отслеживания процесса разработки. Я использую ИИ для обучения, но код полностью пишу сам.

## Как запустить

1. Включить в меню модов Noita **unsafe mods** — без этого мод не получит доступ к `io`
   и логи не запишутся.
2. Включить `synergis`, а для мультиплеера — ещё и `quant.ew`.
3. Играть как обычно: мод сейчас **обычный** (`is_game_mode="0"`), выбирать режим в New Game
   не нужно. Возврат к режиму запланирован на M8.
4. **Для мультиплеера — только обычная сборка.** Игру запускает `noita_proxy.exe`
   (`noita.exe`, **не** `noita_dev.exe`): на dev-сборке не работает NoitaPatcher из EW, и
   синхронизация сущностей не поднимается ([docs/02](docs/02-multiplayer-entangled-worlds.md), §13).
   Для воспроизводимых тестов удобно зафиксировать сид в `proxy.ron`
   (`use_constant_seed:true` и маленький `seed`).

**Важно про отладку.** `logger.txt` в корне игры — лог движка, и вывод Lua туда **частично
попадает**: строки, которым движок может приписать файл, идут как `LUA( <файл> ): <текст>`,
а в обычной сборке — как `LUA: <текст>`. Но полагаться на это нельзя, поэтому у мода есть **свой**
лог через `io`: `logs/init.log` (контекст мода) и `logs/ew.log` (сетевой контекст EW).
`GamePrint` выводит сообщение в ленту прямо в игре. Подробности —
[docs/02](docs/02-multiplayer-entangled-worlds.md), §11.1.

Проверить, что мод подхватился, проще всего по файлу `logs/init.log`: он перезаписывается
на `OnModPreInit`.

## Ограничения, о которых надо помнить

- **Все игроки должны иметь одинаковый набор модов и версий.** Иначе рассинхрон.
- Мод с `request_no_api_restrictions="1"` **нельзя выложить в Steam Workshop.**
  Раздача — через GitHub/архив.
- EW — сторонний мод и ломается при обновлениях Noita. Версию EW стоит зафиксировать.
- Античита нет: клиент сообщает свои попадания сам. Это режим для игры с друзьями.

## Версии и релизы

Версия живёт в двух местах, и они обязаны совпадать:

| где | формат | пример |
| --- | --- | --- |
| git-тег | `v` + версия | `v0.1.0-alpha.1` |
| [`files/version.lua`](files/version.lua) | без `v` | `0.1.0-alpha.1` |

Схема — [SemVer](https://semver.org/lang/ru/), где `MINOR` = этап разработки: `0.1.x` — M2,
`0.2.0` — M3 и так далее до `0.9.0` (M10). `PATCH` — исправления внутри этапа, `1.0.0` — первый
стабильный. Всё до него — «initial development», где ломать совместимость нормально.

Порядок выпуска:

1. обновить [`files/version.lua`](files/version.lua) и [`CHANGELOG.md`](CHANGELOG.md)
   (перенести накопленное из `Unreleased` под новый номер);
2. коммит и `git push origin main`;
3. `git tag -a v0.1.0-alpha.1 -m "..."`, затем `git push origin v0.1.0-alpha.1`;
4. собрать архив **от тега**: `git archive --format=zip --prefix=synergis/ -o synergis-0.1.0-alpha.1.zip v0.1.0-alpha.1`
   (префикс обязателен — иначе у игрока распакуется не в `mods\synergis\`);
5. GitHub → Releases → Draft a new release: тег, описание, архив как asset, для альф — галочка
   **pre-release**.

**Для мультиплеера версии обязаны совпадать у всех игроков.** При расхождении номера RPC
разъезжаются, и это выглядит как загадочный десинк без единой ошибки в логе
([docs/02](docs/02-multiplayer-entangled-worlds.md), §4.1).

## Заметка про `docs/`

Файлы `.md` не входят в список типов, которые Noita выгружает в Workshop
(`.txt .csv .bmp .xml .png .lua .frag .vert .bank .bin .plz`), так что документация
не «утяжелит» мод при публикации.
